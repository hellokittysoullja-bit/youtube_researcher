## 3. Схема событий: первые три для aha, затем 5–10 для внедрения функций
`онбординг · активация · метрики · процесс` · [06:05](https://youtu.be/1XtjFTHrAVQ?t=365)

**Мысль:** Сначала определить первые 2–3 события, которые приводят к aha-моменту; после активации задать 5–10 событий, по которым показывать следующие функции, чтобы не оставлять человека без направления.

**Слова автора:**

> So how to take advantage of custom events in user onboarding how can you think about it right the way you can think about is by thinking about the first initial aha how the users in the first three events they want to do when they come inside the app how do you want to show them the key feature activation and then once you have done this you can show them feature a feature b feature c feature d which is a product adoption side which means that they have understood the value of the app and now it's time to keep helping them discover new features so you can have around five to ten events after user activation event to know what the user should be doing and based on those in-app custom events that user does you show them the next thing so you don't leave them hanging.

**Для Напарника:** Лестница: первая сессия → первая награда на острове → первый ориентир → вечерний чек-ин. Каждая ступень открывается по событию, а не по таймеру.

## 6. Письма по событиям внутри приложения, а не по дням: отклик 70%
`онбординг · уведомления · удержание · метрики` · [10:19](https://youtu.be/1XtjFTHrAVQ?t=619)

**Мысль:** 88% компаний шлют письма по дням, но не по действиям пользователя. Письмо сразу после события (установил расширение) собирает отклик ~70% и ведёт на следующий шаг.

**Слова автора:**

> The fifth mistake that we've seen and this is something that i thought will not be there which is that i thought that a lot of companies are already doing this was when user does something inside the app users get an in-app event the behavior triggered event which is aligned to an email so the email automation is not a new norm in email automation is there so whatever the user does something inside the app you send them event hey great you did something this is the next step so not only in app also but also out app onboarding is really important and the reason why i'm saying is because we you see this email that was fast is when the user actually installed the chrome extension in user pilot so in user pilot the first thing user should when they sign up we tell them to install the chrome extension as you see in the welcome stream and the second thing we tell them after installing the chrome extension is to is to install the javascript these are two big events or install triatric triggering experience so what we found out that after right away when the user uses an in-app event does an in-app event we get we send them an email and the email responders was 70 so this was the best practice that we found out which works for us and we found out that 88 percent of sas company did not send any email based on in-app triggers yes they do send it based on days but in-app events are still missing which means that if the user does something in the first 60-minute or two hours of initial onboarding you should you should if they have achieved something they've done something you take them to the next step by showing them an ex email which was again missing and we do recommend that to connect your in-app on-boarding to out-app onboarding to completely give a great experience to the user.

**Для Напарника:** Если когда-нибудь будут уведомления: только в ответ на действие и с тёплым следующим шагом, не «ты пропустил». Подтверждение события голосом кота, не toast.
