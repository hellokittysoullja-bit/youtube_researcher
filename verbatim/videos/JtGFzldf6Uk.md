# Laws of UX: Hick's Law (with examples!)

**Канал:** AM Design · 14 мин · субтитры: en (авто YouTube) · https://youtu.be/JtGFzldf6Uk

> «Слова автора» — дословный текст из транскрипта (убраны только um/uh и заикания; в авто-субтитрах мало знаков препинания). «Мысль» и «Для Напарника» — вывод разметчика, это не речь автора.

## 1. Пять выводов из закона Хика
`юзабилити · онбординг · СДВГ` · [00:32](https://youtu.be/JtGFzldf6Uk?t=32)

**Мысль:** Минимизировать выбор там, где важна скорость; дробить сложные задачи; выделять рекомендуемый вариант; прогрессивный онбординг; но не обобщать категории так, что пропадает понимание.

**Слова автора:**

> Reduce his cognitive load so what are the takeaways from this particular point well the takeaway as you can see in front of you is we have to minimize choices when response times are critical to increase decision time the second one is break we have to break complex tasks into smaller tasks obviously the third one is we have to avoid overwhelming users by highlighting let's say recommended options that we want them to choose this is something that i'll show you in some let's say pricing tables the fourth one is we have to use progressive onboarding so for example with matrimo slag discord we have a lot of these like onboarding flows and these onboarding flows really help users get into the process and gain some familiarity by going through steps and the fifth one is we have to be very careful not to be so less in terms of let's say categories or items or groups that we lead to abstraction and then the user can't really figure out what those actual options are.

**Для Напарника:** Фокус: мало вариантов и рекомендованный по умолчанию; чек-ин и онбординг пошагово.

## 2. Пошаговый онбординг и подсветка рекомендованного плана
`онбординг · цены · юзабилити` · [06:18](https://youtu.be/JtGFzldf6Uk?t=378)

**Мысль:** Вместо россыпи опций сразу (профиль, команда, уведомления) шагами; на странице тарифов выделяется рекомендуемый тариф.

**Слова автора:**

> Have onboarding experiences this is an example of the matter most onboarding experience so once you actually get the app running you have some options to let's say complete your profile name your team set up desktop notifications inviting team members to your team so on and so forth so you can basically instead of let's say presenting all of those options immediately and the user's face we can actually have a step-by-step sort of an onboarding experience and slack does something similar and a lot of applications do something similar with their onboarding experiences the other thing that i would recommend is highlighting recommended options now here's an example of envision and as we can see they have a multiple pricing plans but they're actually highlighting something that makes the user's choice that much easy and also they're actually incentivizing users in one way or the other to actually choose the option that they themselves recommend so that's one good way of actually narrowing down the items by highlighting the popular one similarly here we can see that on interaction design foundation they're actually highlighting one of the items even though that item is cheaper but that's the one that they probably think that users are gonna use the most so they're actually making the button blue and making it a bit more prominent.

**Для Напарника:** Один вопрос за визит (eveningOffer/nameOffer/checkinOffer) соответствует этому; на странице цен выделять один план.

## 3. Прогрессивное раскрытие на примере Google: показывай вход, а не все функции
`юзабилити · иерархия · СДВГ` · [08:40](https://youtu.be/JtGFzldf6Uk?t=520)

**Мысль:** Google показывает только поле поиска, остальные категории и инструменты появляются после поиска и внутри «инструментов»; открывай точку входа к редким опциям, а не сами опции.

**Слова автора:**

> Another example like again this particular example is not necessarily just applied to forms this can actually be applied to experiences or let's say actions that the user performs so here's an example of google so if you actually go on google.com the only thing that you see like primarily centered on the page are just some search options you basically have an input field you can type something in there and then you can basically hit enter or search so as you can see they've actually reduced all a lot of cognitive load from the user and it allows users to actually just get right into the gist of searching for things once a user has searched for example if i search for nasa i have some of the other options as well i can obviously see some of the results i can actually search for images news articles videos so on and so forth so all of these other options weren't really presented on the previous one i know some of them were like images etc but not all of them so again they're actually allowing use reducing cognitive load by allowing users to do one step at a time search and then do something else do acquire some of the other categorization that's available in the application so if for example a person presses images you can see that they can see obviously the images but then for example if they want to sort further or filter these images further we have some other tools on the right hand side as well so again even though they have tools that allow the image search to be much more powerful even that particular thing is hidden because if users don't want that why present it all the time because that would increase cognitive load right so once a person clicks on tools as you can see we have some other options that are visible here and even in these tools we have categorization even in these tools if a person wants to change the size or the type of the image they can do that by going to that specific category rather than having everything visible now some people may think like hey if we have so much functionality and if we have so much features why don't we surface them why should these be hidden well especially in this case these may not necessarily be something that the user is even willing to use we don't even know if he wants to use it so it's good to actually surface the entry point for some of these optional things that the user can do rather than actually presenting them all of the time because that's going to be disruptive for your larger audience.

**Для Напарника:** Дом и Фокус: главная цель на виду, редкие настройки спрятаны за одним входом.

## 4. Иконки без подписей неоднозначны: добавляй подписи
`иконки · юзабилити · доступность` · [11:56](https://youtu.be/JtGFzldf6Uk?t=716)

**Мысль:** Даже «универсальные» иконки (сетка, питание, график) понимают по-разному; Facebook намеренно подписывает привычные иконки.

**Слова автора:**

> Well one thing to avoid is this particular design and what i'm particularly highlighting here are is the navigation at the bottom now using icons like this is actually a design that i did just for presentation on dribble this is an actual app but even that presentation even though i think the application looks good but when you actually reduce the number of items in let's say icons are using icons the icons sometimes aren't really relatable to a lot of users having universal icons or using universal icons is really good but it's really hard to actually know what those universal icons are and whether your icon is truly a universal icon so imagine we have something like this looks like a grid maybe people recognize it but what does a grid tell me like does it actually tell me that i would be able to see all of the rooms and devices here probably not right similarly i have the power button here maybe i don't know what this means like i'm like i know what this means but i'm not sure if all users would similarly we have a graph here some people may consider it to be different so this is a flaw of this particular design that even if you do categorize like categorize it in a way that makes sense to the user and it's relatable now one simple fix for this would be to add labels right beneath them similar to what facebook does so even though these are some icons that i think are very recognizable to most users like the home icon the friends list the profile so on and so forth but they've actually intentionally added labels and those labels help differentiate these icons clarify them and make them less ambiguous right so that's a really good thing to follow.

**Для Напарника:** Таб-бар AppNav (Дом, Фокус, Мир) должен быть с текстовыми подписями рядом с иконками.
