## Знания

### Хаптика по парной модели нажатие/отпускание (press/release)
- **Суть:** Хаптика на клик нужна, чтобы симулировать физическую кнопку, а физическая кнопка — это ПАРА событий: нажатие и отпускание. Поэтому хаптика на UI-элемент проектируется парой эффектов, а не одним «бззз». Android отдаёт для этого готовые пары констант.
- **Конкретика:** `HapticFeedbackConstants`: `KEYBOARD_PRESS` / `KEYBOARD_RELEASE` (клавиатура), `VIRTUAL_KEY` / `VIRTUAL_KEY_RELEASE` (любой кликабельный элемент). Вызываются через `view.performHapticFeedback(...)`. Требуют View.
- **Дословно:** «just remember the pairwise interaction of press and release and go find your haptic constants»
- **Источник:** 00jRoEFnpk8 [00:31]–[02:35]
- **Спор/нюанс:** Flinto-ролик (8uoZC3Q87Ao) делает то же визуально: отдельные состояния touch down → pressed, touch up → hover. Сходится: «нажатие» и «отпускание» — два разных события обратной связи.
- **[Для Напарника]** В `lib/haptics.ts` нет понятия парного отклика. Для «тяжёлых» действий (старт сессии) можно рассмотреть слабый тик на нажатие и основной отклик на подтверждение — но только на событиях мира, в рамках принципа §4.

### Haptic texture — слабые, но чёткие повторяющиеся тики при жесте
- **Суть:** Во время непрерывного жеста (крутить колесо времени, тянуть ручку выделения текста) хаптика сопровождает каждый дискретный шаг значения — «виртуальная засечка под пальцем». Такие эффекты должны быть subtle yet crisp, потому что повторяются очень быстро: сильный эффект при частом повторе превращается в шум.
- **Конкретика:** Константы `CLOCK_TICK` (часы: выставление времени жестом по циферблату), `TEXT_HANDLE_MOVE` (когда выделение меняется на букву/слово). Хаптика срабатывает на СМЕНУ дискретного значения, а не на каждый пиксель движения.
- **Дословно:** «haptic texture is recommended to be subtle yet crisp because it has to be repeated very quickly»
- **Источник:** 00jRoEFnpk8 [01:33]–[02:35]
- **[Для Напарника]** Прямое подтверждение исключения из §4 CLAUDE.md: пикер длительности = «clock tick». Тики только при реальной смене значения и самые лёгкие по силе. Если делать перетаскиваемый выбор длительности (слайдер минут), тик на каждую 5-минутку — канонический паттерн.

### VibrationEffect: сила важнее семантики, работает без View
- **Суть:** Второй Android-API — `VibrationEffect` через Vibrator service. Выбирать его, когда важна сила отклика, а не смысл жеста; плюс его можно вызвать без View — из фонового сервиса (уведомить пользователя без UI).
- **Конкретика:** Пресеты: `EFFECT_CLICK` (средний, «very crisp nice feeling on modern devices», рекомендован по умолчанию), `EFFECT_TICK` (легче), `EFFECT_HEAVY_CLICK` (сильнее, интенсивнее), `EFFECT_DOUBLE_CLICK` (два клика подряд). Вызов: `VibrationEffect.createPredefined(...)` (в речи — «create pre-baked»). Кастомный: `createWaveform(timings[], amplitudes[])`; пример: амплитуда 255 на 100 мс → 0 на 200 мс → половинная (~128) на 300 мс. Амплитуда 0–255.
- **Источник:** 00jRoEFnpk8 [02:35]–[04:41]
- **[Для Напарника]** Иерархия силы tick < click < heavy click < double click — готовая шкала для `hapticReaction` < `hapticDone` < `hapticReward` < `hapticRare`. Double click как «редкое» событие отличим тактильно.

### Web Haptics: хаптика в мобильном вебе, включая iOS
- **Суть:** NPM-пакет web-haptics даёт сайту хаптику на Android и iOS, чтобы веб ощущался как нативное приложение. Одна функция `trigger`. Его подхватили в Twitter, внедрил Polymarket (со слов автора).
- **Конкретика:** React-хук `useWebHaptics()` → `{ trigger, cancel, isSupported }`; есть хелперы для React, Vue, Svelte и vanilla JS. Опция `debug: true` — на десктопе проигрывает звук, имитирующий вибрацию (для разработки). Пресеты из `defaultPatterns`: bars, error, heavy, success и др. Кастомный паттерн — массив объектов `{ delay (мс от предыдущей вибрации), duration (мс), intensity (0..1, 1 — самая сильная) }`. На сайте пакета есть редактор паттернов: клик добавляет вибрацию, перетаскивание по горизонтали — длительность, по вертикали — интенсивность, кнопка play; можно открыть на телефоне и прочувствовать.
- **Механизм iOS:** `navigator.vibrate` работает на Android, но в iOS поддержки нет совсем. Обход: на iOS тап по `<input type="switch">` даёт системную хаптику. Библиотека программно кликает невидимый switch столько раз, сколько нужно для паттерна. `showSwitch: true` показывает этот switch при отладке. В коде: если `navigator.vibrate` поддержан — используется он, иначе — клики по switch.
- **Дословно:** «it essentially clicks an invisible switch for us that mimics our vibration pattern»; «I hope Apple don't find a way to patch this»
- **Источник:** zAbQE6K0d1k [00:00]–[04:36]
- **Спор/нюанс:** Хрупкость: это обход, Apple может его закрыть. Интенсивность на iOS через switch, по всей видимости, не регулируется (в ролике не сказано явно — не утверждаем).
- **[Для Напарника]** Ключевое для `lib/haptics.ts`: если сейчас там только `navigator.vibrate`, то на iPhone хаптики нет вообще. Трюк со switch (iOS 17.4+ Safari, `<input type="checkbox" switch>`) или сам пакет — способ включить хаптику для большинства русскоязычных iPhone-пользователей. Проверить текущую реализацию.

### Дефолтная вибрация слишком тяжёлая для UI-фидбэка — нужны градации
- **Суть:** Стандартная вибрация движка (Unity `Handheld.Vibrate()`) — «really heavy». Для UI-фидбэка нужна лёгкая хаптика, но системные градации доступны только через нативные библиотеки или сторонние пакеты.
- **Конкретика:** Пакет CandyCoded HapticFeedback (MIT): `HapticFeedback.LightFeedback()`, `MediumFeedback()`, `HeavyFeedback()`. В Unity XR: `controller.SendHapticImpulse(intensity 0..1, duration)`; пример значений: grab 0.7/0.3с; hover enter 0.3/0.3; select enter 0.5/0.3; остальные события — 0 (выключено). В React Native — пакет react-native-haptic-feedback (light/hard варианты; со слов автора есть баги).
- **Источник:** KLorLToQ3mY [03:39]–[06:43]; HxqnDww2Fjo [01:02], [07:14]; 9ZkiY373CHk [01:31]–[02:02]
- **Спор/нюанс:** Valem отмечает: хаптика, повешенная на интерактор, срабатывает одинаково для ВСЕХ объектов — поэтому лучше настраивать хаптику на каждый объект/событие отдельно (hover слабее, чем select).
- **[Для Напарника]** Разная сила на разные события — уже принцип проекта. Hover-хаптики в вебе нет, но аналог «наведение слабее выбора» — tick на смену в пикере против click на подтверждение.

### Когда хаптика добавляет ценность, а когда раздражает
- **Суть:** Хаптика может сопровождать каждый скролл, свайп или тап, поэтому важно понимать, когда она полезна, а когда надоедает. Два типа: temporary (короткий импульс) и continuous (последовательность ощущений).
- **Конкретика:** Применения: напоминания/будильники/задачи; приложения для звонков; фитнес (упражнения, шаринг); чаты (новые сообщения, приглашения). Пять видов тактильных технологий: force feedback, ultrasonic, electrotactile, thermal, vibrotactile (рецепторы кожи ловят вибрации до ~1000 Гц). Рынок тактильных технологий — 19 млрд $ к 2025 (со слов автора, прогноз).
- **Источник:** cK9qsdLf58I [03:06]–[04:39]
- **[Для Напарника]** Поддерживает принцип «хаптика на событие, не на каждый тап».

### Микровзаимодействие = машина состояний + жесты-переходы
- **Суть:** Микровзаимодействие на одном экране (кнопка, свитч, лайк, лоадер) проектируется как набор состояний и переходов между ними, а не как набор отдельных экранов. Каждому состоянию нужен ОБРАТНЫЙ переход, иначе элемент «залипает».
- **Конкретика:** Кнопка: initial → (mouse over) → hover (фон светлее) → (touch down) → pressed (фон заметно темнее) → (touch up) → hover → (mouse out) → initial. Свитч: off ⇄ on по tap, плюс swipe right/left на кружке. Лайк-сердце: две наложенные иконки (серая и красная с opacity 0), состояние liked = opacity красной 100%. Тайминг перехода — spring или classic. Один раз собранное поведение копируется в любые места и экраны; идея «behaviors guide» вместо style guide — библиотека компонентов вместе с их интерактивом. Пример — копия анимации лайка Twitter.
- **Дословно:** «instead of a style guide you have a components guide… your behaviors guide»
- **Источник:** 8uoZC3Q87Ao [00:30]–[13:28]
- **Спор/нюанс:** Elizabeth Alli (O6o5AtU2p10) даёт то же определение: UI-анимация — это смена состояний A→B плюс условия (триггеры и ответы).

### Real-time vs non-real-time анимация
- **Суть:** Non-real-time: после триггера анимация проигрывается по заданной хореографии от начала до конца, пользователь «заперт» в просмотре. Real-time (interactive): анимация реагирует на действия пользователя непосредственно (пример — капча, где нужно поймать мух).
- **Конкретика:** Три контекста: анимированные мокапы (Dribbble, реклама, не функциональные), прототипы (Figma, ProtoPie — для тестирования юзабилити), живые продукты (переходы страниц, микровзаимодействия, лоадеры). Процесс: концепт/сториборд → графика в Figma/XD/Sketch/Penpot (PNG при прозрачности, SVG для масштабирования и кода) → инструмент (Rive со state machine, ProtoPie и др.) → handoff (Lottie/JSON, видео) → реализация: простое — CSS, сложное — JS (GSAP, anime.js, three.js, Framer Motion).
- **Источник:** O6o5AtU2p10 [00:00]–[07:12]
- **[Для Напарника]** Хореография RevealIsland — non-real-time, значит должна быть короткой или пропускаемой; кот, реагирующий на тап/перетаскивание, — real-time, и это сильнее для ощущения присутствия.

### 12 принципов UX в движении (UX in Motion)
- **Суть:** Набор свойств/техник для выбора нужной анимации.
- **Конкретика:** easing (скорость → естественность); offset & delay (разное время старта — глубина и фокус); parenting (связанные элементы показывают отношения); transformation (размер/форма); value change (анимация чисел/прогресса); masking (показать/скрыть часть); overlay; cloning; obscuration (частичное перекрытие); parallax (фон и передний план с разной скоростью — глубина); dimensionality (симуляция 3D); dolly & zoom (движение камеры).
- **Источник:** O6o5AtU2p10 [05:08]–[06:10]
- **[Для Напарника]** Value change — для счётчика минут/ориентиров на финале сессии; parallax — для гряды ориентиров AppBackdrop (медленно, в духе §3).

### Не перебарщивать, думать о чувствительных к движению, иметь «выключатель»
- **Суть:** Большинство сложных анимаций с Dribbble — витрина навыков, а не реальный продукт. В продукте они дают медленную загрузку, тяжёлые файлы и много времени на реализацию. Часть людей находит движение отвлекающим или дезориентирующим.
- **Конкретика:** Иметь off switch или запасной вариант (fallback). Анимация оправдана, только если она вызывает восторг (delight), функциональна или информативна; «не анимировать ради анимации».
- **Дословно:** «have an off switch or a fallback planned»; «don't use UI animations just for animation sake»
- **Источник:** O6o5AtU2p10 [07:12]–[07:44]
- **[Для Напарника]** Для СДВГ-аудитории: `prefers-reduced-motion` должен гасить хореографии и аврору; это согласуется с принципом «медленности» и «контингентности» из §3.

### Easing задаёт характер продукта
- **Суть:** Easing — то, что отличает профессиональный сайт от любительского: он задаёт настроение (медленно/быстро/упруго). В реальном мире вещи разгоняются и тормозят, поэтому линейный easing почти никогда не нужен. Открытая (bouncy) кривая даёт карточкам инерцию, и свайп ощущается естественно, а не жёстко.
- **Конкретика:** Тона: «snappy and performant», «fun and springy», «slow and smooth». В CSS — `cubic-bezier(...)` (в DevTools есть пресеты, в сети — генераторы); в GSAP — `ease: "power2"`. Slow in / slow out у Диснея: больше кадров в начале и конце, меньше в середине.
- **Дословно:** «Almost never do you want a linear ease» (Kole Jain); «the easings are becoming the most important part of a website to master» (Larose)
- **Источник:** 9eHEOAn2FOA [03:37]–[04:39]; 14h1VnkQvIc [00:31]–[01:02]; EqMi1AzbFqs [02:05]; QiqSE2XcyDo [02:03] — несколько независимых авторов, высокий сигнал надёжности.
- **[Для Напарника]** Зафиксировать одну «подпись» easing для всего продукта (тёплый, мягкий, без резкого bounce на фоне; лёгкий spring — только на наградах).

### Mask reveal — самая популярная UI/UX техника анимации
- **Суть:** Родитель с `overflow: hidden` служит маской; дочерний элемент сдвинут `transform: translateY(-100%)` (или X) за её пределы и въезжает на место. Используется повсеместно (пример — hello.cuberto.com).
- **Конкретика (7 уровней):** 1) CSS keyframes, 1.7с, `cubic-bezier`; 2) заголовок + подзаголовок, у второго `animation-delay: 0.2s`; 3) несколько строк — каждая строка отдельным элементом, задержки 0.2/0.4с; 4) GSAP `gsap.to('.hide', { duration: 1.4, y: 0, stagger: 0.1, ease: 'power2' })` — stagger избавляет от ручных таймингов (0.7 — слишком медленно для демо); 5) изображение — `clip-path: polygon(...)` от «трапеции-сжатой» к полной + scale в GSAP timeline (`clipPath` в camelCase), генератор CSS Clippy; 6) посимвольный reveal — SplitType (`types: 'chars'`), `gsap.from('.char', { yPercent: -100, stagger: 0.01 })`; stagger 0.1 на символ — «плохо, заставлять ждать», 0.01 — «really nice».
- **Источник:** QiqSE2XcyDo [00:00]–[12:33]; masking также в O6o5AtU2p10 [05:39]; в Jitter — «mask reveal» для QR-кода и прогресс-бара, растущего слева направо (7ai-VuJ6YCo [03:07], [10:54])

### Хореография карточек: одновременность, стаггер и «главное — последним»
- **Суть:** Элементы внутри карточки нужно запускать, пока карточка ещё въезжает — а не ждать окончания её анимации. Затем — стаггер. Последней анимируется самая важная деталь (там, куда нужно направить внимание).

### 12 принципов анимации Диснея применимы к UI
- **Суть:** Из книги «The Illusion of Life» (Ollie Johnston и Frank Thomas, 1981), обобщение работы аниматоров 1930-х. Применимы к персонажам, тексту, логотипам и UI.
- **Конкретика:** squash & stretch (вес и объём, «самый важный»); anticipation (малое действие перед главным — сигнал «сейчас будет»); follow-through & overlapping action (ничто не останавливается разом — части тела догоняют); arcs (движения по дуге, не по прямой); slow in & slow out; timing (больше кадров — медленнее и плавнее, меньше — резче); secondary action (мелкие несущественные движения, добавляющие смысл); exaggeration; staging (направить внимание на главное); straight ahead vs pose to pose; solid drawing; appeal.
- **Источник:** EqMi1AzbFqs [00:00]–[04:38]
- **[Для Напарника]** Кот: anticipation перед реакцией, follow-through хвоста, secondary action (ухо дёрнулось) — источник «живости» без пульсации UI. Но MascotSvg — общий компонент, правки только по явному запросу (§10).

### Свайп-взаимодействия: три категории
- **Суть:** Взаимодействия превращают UI в опыт. На телефоне края экрана — ресурс для уникальных эффектов. Категории: внутри страницы, между страницами, жесты.
- **Конкретика:** Внутри страницы: горизонтальные карточки лучше вертикального стека; bounce-easing даёт инерцию; skew карточек у края экрана — иллюзия 3D-кольца; индикаторы страниц с «жидким», магнитным перетеканием; край экрана как «горизонт», уменьшающий приближающиеся элементы + круговой свайп = ощущение «катушки данных». Между страницами: свайп вверх — карточка расширяется до экрана, чёрная плашка тоже, контент «fade up and in», в конце — эластичный снап; движение ВСЕГДА следует направлению свайпа. Онбординг: кнопка и кликабельная, и свайпаемая; круг расширяется, контент уезжает, круги меняются, новый сжимается — простой трюк. Shared element: картинка карточки зумится и становится hero новой страницы — continuity. Жесты: свайп заменяет кнопку (Apple везде); свайп вниз для закрытия поповеров + фон чуть отъезжает и уменьшается при открытии; slide-to-confirm для необратимых/весомых действий (Resend — отправка письма, покупка крипты): «намного сложнее случайно проскользить слайдер, чем нажать кнопку».
- **Дуальность:** свайп всегда дублируется кнопкой/лонг-прессом для непосвящённых (Gmail: свайп-удаление и кнопка delete).
- **Источник:** 14h1VnkQvIc [00:00]–[05:40]
- **[Для Напарника]** Slide-to-start вместо кнопки «Начать фокус» — превращает старт в маленький осознанный ритуал + защищает от случайного старта; но нужна кнопка-дубль. Continuity: ориентир с горизонта Дома может зумиться в карту Мира.

### Peak-End и serial position: начало и (особенно) конец
- **Суть:** Serial position effect: из серии лучше всего запоминаются первые и последние элементы. Peak-end rule: опыт оценивается не по сумме моментов, а по пику и концу. Вместе: правильно сделанные начало и конец покрывают ~80% того, что запомнят (со слов автора). Конец важнее начала: даже если провалил старт — «stick the ending». Если не закрывать — опыт «проходит как размытое пятно», даже если задача решена.
- **Конкретика:** Приёмы AJ&Smart: 1) Highlight session — показать агенду дня и по пунктам спрашивать «что запомнилось/понравилось/изменилось?» — участники сами создают хайлайты, «аплодисменты себе». 2) Показ прогресса — фото пустой комнаты утром vs заполненной в конце (или скриншоты Miro «3 часа назад было пусто»): чувство прогресса и гордости, closure. 3) Ритуалы старта/конца: лучший кофе (свежеобжаренный) — только в начале, потом машинный; доставка еды/кофе на дом участникам удалёнки; разминки; медитация в конце, «где ты хочешь быть через 2 года». «Не фейдить» начало и конец.
- **Дословно:** «start strong and stronger»; «it shouldn't just fade out»
- **Источник:** So8aseCO3hY [01:05]–[08:50]
- **[Для Напарника]** Финал сессии = пик (RevealIsland) + явное закрытие. Приём «до/после» — показать остров/гряду каким он был в начале сессии и каким стал. «Лучший кофе в начале» — ритуал старта (playStartSigh, разгорание очага). Даже после сорванной сессии — тёплый финал, потому что конец важнее.

### Формула хука: context lean → scroll-stop interjection → contrarian snapback

### Дизайн как ответственность: «designing for dopamine»
- **Суть:** Успех техники мерится временем пользователя, а не пользой. Цитируется Tristan Harris: «race to the bottom of the brainstem». Дизайнеры «на передовой»: их ценности зашиты в каждый user journey, push и «светящуюся иконку». Нужно учить этику, нейронауку, когнитивные искажения, инклюзию; Dieter Rams: «design should not dominate people, it should help people»; less but better.
- **Конкретика:** Мы проверяем телефон 220 раз в день — вдвое чаще, чем думаем (британское исследование, со слов автора). Google и Apple — функции экранного времени и подавления уведомлений. Nextdoor переделывал формы, чтобы бороться с расовым профилированием; приложения женского здоровья Glow и Eve критикуются как сделанные мужчинами.

### Человеческий дизайн против AI-шаблона: why before what, predictive empathy, memory encoding
- **Суть:** AI-лэйауты предсказуемо идеальны и потому забываются. Дизайнер вносит ритм, напряжение, воздух, контролируемый дисбаланс (флакон духов залезает на типографику, тонкая линия ведёт от флакона к цене). Каждый элемент «должен платить аренду». Predictive empathy — проектировать под то, что зритель почувствует через секунды: смягчить крик заголовка, добавить воздуха, одну эмоциональную подсказку (строка-заверение, символ доверия), палитру сменить на успокаивающую — «понят, а не под давлением». Memory encoding — оставить зрителю что-то для разгадки (пластинки складываются в сердце; пустая одежда на стуле): пауза разгадки = момент формирования памяти.
- **Источник:** WFkGbyH24AY [01:01]–[10:54]
- **[Для Напарника]** Predictive empathy = тёплый тон без давления; «пауза разгадки» — для визуальных метафор острова.

## Самое сильное в пачке
- Web-хаптика на iOS работает через программный клик по невидимому `<input type="switch">` — `navigator.vibrate` на iOS не поддерживается вообще → «Web Haptics: хаптика в мобильном вебе, включая iOS».
- Хаптика на клик моделирует физическую кнопку и должна быть парой press/release → «Хаптика по парной модели…».
- Haptic texture при жестах — «subtle yet crisp», только на смену дискретного значения (clock tick) → «Haptic texture…».
- Шкала силы tick < click < heavy click < double click как готовая иерархия событий → «VibrationEffect…».
- Peak-end + serial position: конец важнее начала; закрывать опыт показом «до/после» и хайлайтами, а не фейдом → «Peak-End и serial position…».
- Тизинг растягивает интервал между наградами («It's economical!»), а пейсинг без перерывов в высокой интенсивности истощает → «Новизна + тизинг…», «Engagement без зла…».
- Восторг — от специфичности жеста, а не от его стоимости («one size fits one», хот-дог за 2 $) → «Unreasonable hospitality…».
- В хореографии запускать содержимое карточки, пока карточка ещё въезжает; главное — последним; выход короче входа → «Хореография карточек…».
- Slide-to-confirm для весомых действий и обязательный дубль свайпа кнопкой → «Свайп-взаимодействия…».
- Stagger посимвольного reveal 0.01с, а не 0.1с — иначе пользователь ждёт → «Mask reveal…».
