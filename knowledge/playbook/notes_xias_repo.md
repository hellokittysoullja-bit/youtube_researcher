# Заметки: plugin87/ux-ui-agent-skills (XIAS) — разобран целиком

Что это: набор инструкций и проверок для ИИ-агентов, пишущих UI. 138 дизайн-систем (в т.ч. duolingo, apple, friendly), токены DTCG, 52 объективные проверки (34 открывают реальный браузер).

## Главное для Напарника
- Порядок приоритетов: потребности человека > доступность > консистентность > эстетика > удобство разработки. Вкус никогда не бьёт доступность.
- «Не называй число, которое не измерил»: контраст, «всё ок» — только из вывода проверки. Рендерить и смотреть, кликать каждый контрол.
- Восемь состояний у каждого интерактивного элемента: default, hover, focus, active, disabled, loading, error, selected. Loading не равно disabled (спиннер, полная яркость).
- Одно ведёт: один главный элемент на экран, дисплейный текст минимум 2.5x от основного.
- Экранная экономика: на 390x844 заголовок и главное действие видны без прокрутки; бесконечные анимации — только осознанно (расход батареи на OLED).
- Токен по смыслу: деструктивное — danger, главное — primary, второстепенное — нейтральное. Один смысл — один вариант везде.
- Радиогруппа обязана иметь стрелочную модель клавиатуры (roving tabindex).
- Вкус: нет цветной границы с одной стороны карточки; нет эмодзи вместо иконок; нет #000 на #fff; радиусы и тени варьируются по размеру компонента.
- Голос: глагол в начале кнопки, ошибка = что случилось → почему → что делать; чем выше стресс, тем проще язык; юмор не в ошибках и деструктиве.
- Когнитивная доступность: не заставлять помнить, один главный шаг на экран, показывать «шаг 2 из 4 · ~2 мин», не обязательно прятать единственный путь за жест.

## Как запускать проверки на сайте
Проверки читают готовый HTML. Для Next.js сохраняем отрисованную страницу с встроенным CSS и переводим цвета oklch в rgb (иначе контраст считается неверно). Цвета в oklch их парсер не понимает.

## Дополнение: что дочитано во второй проход
- Критик (`.claude/agents/design-critic.md`): работает в отдельном контексте без доступа к рассуждениям автора, обязан отрендерить экраны, кликнуть все контролы, цитировать только измеренные числа; вердикт reject/rework/ship, три причины отправки назад, таблица находок «серьёзность / находка / доказательство / исправление», не более двух хороших вещей, раздел «чего не мог оценить». Не выдумывать критические находки.
- `grill-me`: до работы задать до 7 вопросов, только те, что меняют результат; всё неспрошенное записать как допущение с ценой ошибки; итог — BRIEF.md.
- Состояния: loading не равно disabled; радиогруппа — один пункт в Tab (выбранный или первый), стрелки двигают и фокус, и выбор, с переходом по кругу.
- Производительность: LCP ≤ 2.5 с, INP ≤ 200 мс, CLS ≤ 0.1; шрифты через next/font (никогда @import); пустой каркас до загрузки JS — это провал LCP (на нашем онбординге было 3.3 с, стало 0.58 с после того, как убрали пустой div).
- Доступность: фокус не должен менять форму элемента; один контур фокуса; forced-colors (Windows High Contrast) — рамка и системные цвета вместо плоских заливок; 2.5.2 отмена нажатия (отпустил раньше — не срабатывает); 1.4.12 интервалы текста.
- Токены движения: fast 100, base 200, moderate 300, slow 500 мс; ease-out для входа, ease-in для выхода, spring (0.34,1.56,0.64,1) только для редкого акцента; при reduce — отключить transform, оставить fade ≤100 мс.
- Библиотека дизайн-систем: 58 из 138 — заглушки до 3.5 КБ (friendly, lingo, default…), ценны только подробные (apple, spotify, airbnb, claude, stripe, linear, notion). Spotify — ближайший к нашему виду: тёмный фон, один зелёный акцент «только функциональный, не декор», кнопки капсом с трекингом, тяжёлые тени на тёмном.
- Не читал: фреймворк-адаптеры (Vue, Swift и др.), workflows про Figma/токен-сборку/управление, evals, CHANGELOG, остальные ~130 брендовых систем.
